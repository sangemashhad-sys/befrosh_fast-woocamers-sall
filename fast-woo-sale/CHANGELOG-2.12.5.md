# تغییرات نسخهٔ ۲.۱۲.۵ — دور یازدهم شکار باگ

> **خلاصهٔ یک‌خطی:** پنج بازبین موازی مستقل روی کل کدبیست (۲۰ فایل PHP + ۲ فایل JS) خط‌به‌خط بازبینی کردند؛ **۲۲ باگ جدید** پیدا شد (۱ بحرانی، ۲ بحرانیِ هم‌ردهٔ سقوط فرانت، ۳ حیاتی، ۵ متوسط، ۱۳ کم‌اهمیت) که هر ۲۲ مورد شخصاً راستی‌آزمایی و اصلاح شد. مهم‌ترین یافته: یک **فتالِ بازگشتی که نسخهٔ ۲.۱۲.۴ وارد کرده بود** — اگر ۲.۱۲.۴ را نصب کرده‌اید، این نسخه را فوراً نصب کنید.

## چرا این نسخه حیاتی است؟ (F-24)

در نسخهٔ ۲.۱۲.۴ برای رفع باگ F-09 (فروپاشی هویت پشت CDN)، متد `get_client_ip()` به‌صورت `static` اعلام شد تا Tracker هم بتواند صدا بزند — اما بدنهٔ متد هنوز از `$this->` استفاده می‌کرد. در PHP، `$this` داخل متد استاتیک هرگز در دسترس نیست؛ با آزمایش عملی روی PHP 8.4 و 7.4 تأیید شد که **هر سه شیوهٔ فراخوانی** (`Class::method()`, `self::` از متد نمونه، `$obj->`) فتال «Using $this when not in object context» می‌دهند.

نتیجه روی ۲.۱۲.۴:
- هر ۶ اندپوینت AJAX افزونه (افزودن سریع، پکیج، کوپن خروج، آپسل تشکر، تازه‌سازی nonce، بیکان ردیابی) → **۵۰۰**
- هر صفحه‌ای که ویجت ردیابی‌شده رندر می‌کند (نمایش → هش سشن → `get_client_ip`) → **۵۰۰ وسط رندر**

این خطا ازLint نحوی عبور می‌کند (خطای زمان اجراست) و چون ادمین کار می‌کرد، فروشگاه «بی‌صدا» از کار می‌افتاد. در ۲.۱۲.۵ هر پنج متد کمکی IP استاتیک شدند (هیچ وابستگی به نمونه ندارند) و `$this->` به `self::` تبدیل شد.

## چیزهایی که دیده شد ولی عمداً «باگ» شمرده نشد

- **پنجرهٔ میکروثانیه‌ای fail-open در rate-limiter کش‌محور** (F-A4 دور داخلی): خودش در درخواست بعدی جبران می‌شود؛ پیچیدگی بیشتر، ریسک بیشتر.
- **دو برابر شدن مرزی در سقف پنجرهٔ ثابت rate-limiter** (F-A5): رفتار استاندارد لیمیت‌رهای پنجرهٔ ثابت؛ ضد DoS است نه صورتحساب.
- **عدم استفادهٔ هوک‌های حذف/بازگردانی سشن پکیج از قفل F-23** (F-A8): مسابقهٔ نادر بین حذف و افزودن همزمان یک سشن؛ نتیجه خودجوش همگام می‌شود و استخراج هلپر مشترک، ریسک ریفکتور بر سه فایل حساس را نمی‌ارزد.
- **شمارنده‌های تجمیعی A/B از ابتدای تست** (بحث بازبینی دور ۷): امروز خنثی است — شمارش DISTINCT و سقف سنی ۳۰ روزه برقرار است؛ «قهرمان پیر» تصمیم طراحیِ مستندشده است، نه خطا.

## سازگاری

- **PHP 7.0+** حفظ شد (بدون `??=`، بدون arrow fn؛ `Throwable` در F-44 از PHP 7.0 مجاز است).
- **ووکامرس ۸.۰ تا ۹.x**: F-30 دقیقاً برای ۸.x است؛ F-43/F-44 مستقل از نسخه.
- **HPOS فعال/غیرفعال**: F-27 و F-40 در هر دو مسیر درست کار می‌کنند (متای سفارش از API ترجمه می‌شود).
- **تغییر شِما**: فقط ایندکس `user_id` روی `fws_events` (dbDelta خودکار در اولین درخواست پس از ارتقا؛ برای جدول‌های خیلی بزرگ چند ثانیه قفل متادیتای MySQL ممکن است).
- **تنظیمات/کلیدهای جدید پنل**: هیچ — نه کلید جدید، نه گیت جدید (قاعدهٔ طلایی دست‌نخورده).
- **ریاضیات مبلغ‌ها و شارژ**: هیچ تغییری (F-31/F-33 فقط پیام و شمارش صادقانه‌اند).

## روش کار این دور

۵ عامل بازبین مستقل (research-only) روی ۵ خوشهٔ فایل + بازخوانی کامل ۶۵۶ خط worklog برای جلوگیری از گزارش‌های تکراری؛ هر یافته پیش از اصلاح، شخصاً روی سورس راستی‌آزمایی شد (شامل آزمایش عملی معناشناسی استاتیک PHP با باینری واقعی و مقابلهٔ کوئری‌ها با sql_mode پیش‌فرض MySQL 8). اعتبارسنجی نهایی: ۲۰/۲۰ فایل PHP با php-parser بدون خطا، هر دو فایل JS با node --check سالم.
