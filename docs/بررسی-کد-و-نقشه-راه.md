# بررسی کد افزونه Fast Woo Sell و نقشه راه

> این سند نتیجه‌ی یک بررسی کامل روی کد فعلی مخزن است. هدفش این است که بدانی **دقیقاً چه چیزی داری**، **چه چیزی کم است** و **قدم بعدی چیست**.

---

## ۱. در یک نگاه

افزونه‌ی `fast-woo-sell` یک افزونه‌ی ووکامرسی برای «افزایش فروش» است که سه قابلیت را وعده می‌دهد:

1. پیشنهاد هوشمند محصول
2. پیگیری سبد خرید رها شده
3. پیش‌بینی موجودی انبار

و یک تعهد مهم دارد: **همه‌ی پردازش‌ها محلی انجام می‌شود و هیچ داده‌ای به بیرون ارسال نمی‌شود.**

| شاخص | مقدار |
|---|---|
| تعداد فایل | ۵۴ فایل |
| تعداد خط PHP | ۱۰٫۲۶۲ خط |
| معماری | کلاس‌محور، namespace `FWS\`، اتولودر اختصاصی |
| حداقل نسخه‌ها | PHP 7.4 · WordPress 6.2 · WooCommerce 8.0 |
| تست | فقط ۱ فایل تست واحد (Requirements) |
| پنل مدیریت | ❌ ندارد |
| نمایش در فروشگاه | ❌ ندارد |
| سبد رها شده | ❌ ندارد (فقط جدول دیتابیس‌اش ساخته می‌شود) |
| پیش‌بینی موجودی | ❌ ندارد (فقط جدول دیتابیس‌اش ساخته می‌شود) |

**جمع‌بندی یک‌خطی:** «موتور» افزونه بسیار خوب و حرفه‌ای نوشته شده، ولی **هیچ دریچه‌ای برای کاربر ندارد**. نه مشتری چیزی می‌بیند، نه مدیر فروشگاه می‌تواند چیزی را تنظیم کند. عملاً الان یک کتابخانه‌ی داخلی است، نه یک افزونه‌ی قابل استفاده.

## ۲. نقشه‌ی فایل‌ها و کاری که هر بخش می‌کند

### ریشه‌ی افزونه

| فایل | کار |
|---|---|
| `fast-woo-sell.php` | فایل اصلی: هدر افزونه، ثابت‌ها، دروازه‌ی پیش‌نیازها، هوک‌های فعال/غیرفعال‌سازی |
| `uninstall.php` | حذف کامل داده‌ها، فقط اگر مدیر صریحاً اجازه داده باشد |
| `composer.json` | ابزارهای توسعه: PHPCS، WPCS، PHPCompatibility، PHPUnit |
| `phpcs.xml.dist` | استاندارد کدنویسی وردپرس + سازگاری PHP |
| `phpunit.xml.dist` | تنظیمات تست |

### `includes/Core/` — هسته

| کلاس | کار |
|---|---|
| `Requirements` | چک کردن PHP / WP / WC و نمایش پیام «غیرفعال است» با راهنما |
| `Compatibility` | اعلام سازگاری با HPOS و Cart/Checkout Blocks ووکامرس |
| `Config` | تمام تنظیمات در **یک** آپشن autoload‌شده (`fws_settings`) با حدود ۵۰ کلید |
| `State` | وضعیت داخلی (نسخه اسکیما، cursor، epoch کش) در آپشن‌های **بدون** autoload |
| `Cron` | ۶ زمان‌بندی: rollup ساعتی، affinity روزانه، اسکن سبد، صف، پیش‌بینی، پاکسازی |
| `Plugin` | ثبت و راه‌اندازی کامپوننت‌ها؛ هر کامپوننت جداگانه در try/catch تا یک خطا کل سایت را نخواباند |
| `Autoloader` | نگاشت `FWS\` به پوشه‌ی `includes/` |
| `Hookable` | قرارداد هر کامپوننت: `register_hooks()` |

### `includes/Install/` — نصب

| کلاس | کار |
|---|---|
| `Schema` | ساخت ۱۳ جدول در ۴ فاز (core / carts / forecast / optimise) با `dbDelta` |
| `Migrator` | اجرای DDL فقط در admin و cron، با قفل، تا فرانت‌اند هرگز DDL اجرا نکند |
| `Installer` | فعال‌سازی تک‌سایت و شبکه‌ای (تا ۵۰۰ سایت)، نصب در سایت‌های جدید مالتی‌سایت |
| `Capabilities` | چهار دسترسی اختصاصی: `fws_view_reports`، `fws_manage_settings`، `fws_manage_carts`، `fws_export_data` |

### `includes/Tracking/` — ردیابی (قلب داده‌ی افزونه)

| کلاس | کار |
|---|---|
| `Visitor` | شناسه‌ی بازدیدکننده در کوکی **httpOnly** (`fws_v`) با ساختار `visitor|session|last_seen`؛ نشست جدید بعد از ۳۰ دقیقه بی‌کاری؛ احترام به DNT و GPC |
| `EventType` | ۱۳ نوع رویداد با برچسب فارسی |
| `EventRepository` | درج تکی و دسته‌ای، شمارش، حذف بر اساس نگهداری |
| `EventRecorder` | سیاست ثبت رویداد، سقف‌ها، dedupe |
| `ServerEvents` | هوک‌های ووکامرس: افزودن به سبد، حذف، تغییر تعداد، مشاهده تسویه، سفارش جدید، پرداخت، تغییر وضعیت |
| `RestController` | مسیر `POST /fws/v1/collect` با چک same-origin، nonce اختیاری، محدودیت نرخ |
| `Rollup` | تجمیع ساعتی رویدادها در جدول‌های آماری روزانه |
| `Cleanup` | پاکسازی بر اساس سیاست نگهداری (۹۰ / ۷۳۰ روز) |
| `Assets` + `assets/js/tracking.js` | اسکریپت فرانت‌اند: ثبت بازدید، ثبت نمایش پیشنهاد با `IntersectionObserver` و شرط dwell ۷۰۰ms، ثبت کلیک، ارسال دسته‌ای با `sendBeacon` |

### `includes/Recommendation/` — موتور پیشنهاد

| کلاس | کار |
|---|---|
| `Engine` | قرارداد یک موتور پیشنهاد (فقط رتبه‌بندی، نه فیلتر موجودی) |
| `Registry` | ثبت ۹ موتور با ترتیب اولویت: AlsoBought → Personal → AlsoViewed → ManualRelated → RecentlyViewed → Trending → BestSellers → SameCategory |
| `Context` / `ContextFactory` | ساخت زمینه‌ی درخواست: صفحه‌ی محصول، سبد، تسویه، سفارش، آرشیو |
| `Filters` | فیلتر موجودی، عدم نمایش، اقلام داخل سبد، خریدهای قبلی، سقف هر دسته |
| `Cache` | کش transient با `epoch` و کلید اثر انگشت زمینه؛ نتایج شخصی هرگز کش نمی‌شوند |
| `Service` | تنها نقطه‌ی ورود: over-fetch، زنجیره‌ی موتورها، حداقل نتایج |
| `AffinityBuilder` + `AffinityRepository` | ساخت جدول هم‌رخدادی (خرید همزمان / مشاهده همزمان) به‌صورت دسته‌ای و قابل ادامه با cursor |
| `RankingRepository` | پرفروش‌ها، محبوب‌های اخیر، بازدیدهای اخیر، خریدهای کاربر |

## ۳. چه چیزهایی هست ولی «هیچ‌جا استفاده نمی‌شود»

این‌ها نوشته شده‌اند اما **هیچ کدی آن‌ها را صدا نمی‌زند**:

| مورد | وضعیت |
|---|---|
| `Recommendation\Service` | موتور پیشنهاد آماده است ولی در هیچ نقطه‌ای از فرانت‌اند یا پنل صدا زده نمی‌شود |
| `Capabilities` | چهار دسترسی تعریف و نصب می‌شود ولی هیچ صفحه‌ای از آن‌ها استفاده نمی‌کند |
| جدول `fws_placements` | ساخته می‌شود، هیچ کدی آن را نمی‌خواند یا نمی‌نویسد |
| جدول `fws_carts` و `fws_cart_log` | ساخته می‌شوند، ماژول سبد رها شده وجود ندارد |
| جدول `fws_forecast` | ساخته می‌شود، ماژول پیش‌بینی موجودی وجود ندارد |
| جدول‌ها‌ی `fws_rules`، `fws_segments`، `fws_experiments`، `fws_experiment_variants` | ساخته می‌شوند، ماژول شخصی‌سازی و آزمایش A/B وجود ندارد |
| `Cron::SCAN_CARTS`، `Cron::QUEUE`، `Cron::FORECAST` | زمان‌بندی می‌شوند ولی **هیچ listener ندارند** — یعنی این سه کرون بی‌دلیل اجرا می‌شوند |
| `EventType::CART_ABANDONED`، `RECOVERY_SENT`، `RECOVERY_CLICKED`، `ORDER_ATTRIBUTED` | تعریف شده‌اند، هیچ‌وقت ثبت نمی‌شوند |
| `State::ONBOARDED` | کلید ویزارد راه‌اندازی، ولی ویزاردی وجود ندارد |
| تنظیمات آزمایش (`experiment_min_samples` و…) | در `Config` هست، ماژولش نیست |

## ۴. چه چیزهایی کاملاً غایب است

### ۴.۱ پنل مدیریت — ❌

هیچ منویی، هیچ صفحه‌ای، هیچ فرمی وجود ندارد. یعنی:

- مدیر فروشگاه نمی‌تواند افزونه را روشن/خاموش کند (فقط با فیلتر PHP ممکن است)
- نمی‌تواند ببیند چه آماری جمع شده
- نمی‌تواند ببیند موتور پیشنهاد روی محصول‌هایش چه نتیجه‌ای می‌دهد
- نمی‌تواند affinity را دستی بسازد یا کش را خالی کند

> `Config::update()` نوشته شده و هیچ‌کس آن را صدا نمی‌زند.

### ۴.۲ نمایش پیشنهادها در فروشگاه — ❌ (اولویت تو)

هیچ هوکی روی صفحه‌ی محصول، سبد، تسویه یا صفحه‌ی تشکر اضافه نشده. هیچ شورتکد، ویجت یا بلوکی هم وجود ندارد. هیچ CSS‌ای هم وجود ندارد.

نکته‌ی مهم: `assets/js/tracking.js` یک «قرارداد مارک‌آپ» تعریف کرده:

```html
<div data-fws-placement="12" data-fws-engine="also_bought" data-fws-variant="a" data-fws-surface="product">
  <a data-fws-product="123" data-fws-variation="0">…</a>
</div>
```

یعنی طراح اصلی این افزونه دقیقاً می‌دانسته که قرار است چه HTML‌ای تولید شود — ولی کدی که آن HTML را بسازد **هنوز نوشته نشده**. تا وقتی آن کد نوشته نشود، رویداد «نمایش پیشنهاد» و «کلیک پیشنهاد» هیچ‌وقت ثبت نمی‌شود و آمار attribution خالی می‌ماند.

### ۴.۳ بازگردانی سبد رها شده — ❌

جدول‌هایش هست، تنظیماتش هست (`cart_abandon_minutes`, `cart_max_attempts` و…)، کرونش هست — ولی کدی که سبد را snapshot کند، رها شده تشخیص دهد، ایمیل بزند و لینک بازیابی امضاشده بسازد وجود ندارد.

### ۴.۴ پیش‌بینی موجودی — ❌

همان وضعیت: جدول و تنظیمات هست، محاسبه‌گر و گزارش نیست.

### ۴.۵ زبان و ترجمه — ⚠️ نیمه‌کاره

- پوشه‌ی `languages/` فقط یک `README.md` دارد؛ **هیچ فایل `.pot` یا `.po` یا `.mo` وجود ندارد**
- متن‌های مبدأ **فارسی** نوشته شده‌اند (مثل «بازدید محصول»)
- نتیجه: روی یک سایت انگلیسی‌زبان، همه‌ی متن‌ها فارسی دیده می‌شود

برای هدف دوزبانه بودن، این یک **تصمیم معماری** است:

- **گزینه الف:** متن مبدأ انگلیسی شود + ترجمه‌ی `fa_IR` اضافه شود → استاندارد وردپرس، آماده‌ی انتشار جهانی
- **گزینه ب:** متن مبدأ فارسی بماند + ترجمه‌ی `en_US` اضافه شود → کد فعلی دست‌نخورده می‌ماند ولی غیرمعمول است

پیشنهاد من **گزینه الف** است؛ دلیلش در بخش ۶ آمده.

### ۴.۶ آماده‌سازی انتشار — ❌

| مورد | وضعیت |
|---|---|
| `readme.txt` (مخصوص مخزن وردپرس) | ندارد |
| فایل `LICENSE` | اشاره به GPL هست، خود فایل نیست |
| `.distignore` | ندارد → بسته‌ی نصب باید تست‌ها و فایل‌های دواپ را حذف کند |
| اسکریپت ساخت ZIP | ندارد |
| CI (GitHub Actions) | ندارد |

## ۵. نکاتی که در کد دیدم و بهتر است اصلاح شوند

| # | موضوع | توضیح |
|---|---|---|
| ۱ | وعده‌ی نادرست در توضیحات | هدر افزونه می‌گوید سبد رها شده و پیش‌بینی موجودی دارد، ولی ندارد. کاربر ناامید می‌شود. |
| ۲ | جداول بی‌استفاده | ۹ جدول ساخته می‌شود که هیچ کدی نمی‌خواند → حجم دیتابیس و پیچیدگی پشتیبان‌گیری بی‌دلیل |
| ۳ | کرون‌های بی‌listener | سه کرون هر ساعت/روز اجرا می‌شوند و کاری نمی‌کنند |
| ۴ | موتور پیشنهاد بدون خروجی | بهترین کد پروژه، بیرون از پنل و فرانت‌اند کاملاً مرده است |

| ۶ | نبود تست برای منطق اصلی | فقط `Requirements` تست دارد؛ `Service`، `Filters`، `Sanitize`، `Config` تستی ندارند در حالی که منطق حساسی دارند |

نکات مثبتی هم که باید حفظ شوند: جداسازی DDL از فرانت‌اند، کوکی httpOnly، احترام به DNT، quietly-reject در REST، try/catch در راه‌اندازی کامپوننت‌ها، و استفاده از جدول‌های lookup ووکامرس به‌جای join سنگین.

## ۶. نقشه راه پیشنهادی

پیشنهاد من این ترتیب است (اولویت تو «نمایش پیشنهادها در فروشگاه» بود، پس از گام ب شروع می‌کنیم):

### گام الف — پنل مدیریت و تنظیمات
منوی «فروش هوشمند» زیر منوی ووکامرس، صفحه‌ی تنظیمات با تب‌های منطقی، استفاده از چهار capability موجود، ویزارد راه‌اندازی اولیه، صفحه‌ی «سلامت و ابزارها» (ساخت دستی affinity، خالی کردن کش، نمایش وضعیت کرون).

فایل‌های جدید: `includes/Admin/{Menu,Settings,Fields,Notice,Wizard,Tools}.php` و `assets/admin/*`

### گام ب — نمایش پیشنهادها در فروشگاه ⭐ (اولویت تو)
رندرکننده‌ی Placement که موتور `Service` را صدا می‌زند و دقیقاً همان مارک‌آپ موردانتظار `tracking.js` را می‌سازد:
هوک روی صفحه‌ی محصول («مشتریان دیگر هم خریدند»)، سبد («تکمیل خرید شما»)، تسویه، صفحه‌ی تشکر و آرشیو؛ به‌همراه **شورتکد**، **ویجت** و **بلوک** برای استفاده‌ی دلخواه؛ فایل CSS سبک و سازگار با قالب‌های مختلف؛ احترام به `lazy_render`، `show_social_proof` و `shadow_mode`.

فایل‌های جدید: `includes/Frontend/{Placements,Renderer,Hooks,Block,Widget,Shortcode}.php` و `assets/css/placements.css`

### گام ج — بازگردانی سبد رها شده
snapshot سبد، تشخیص رها شدن طبق تنظیمات، ایمیل یادآوری با لینک امضاشده، کد تخفیف اختیاری، لاگ تلاش‌ها، و گزارش سبدهای رها شده در پنل.

### گام د — پیش‌بینی موجودی
محاسبه‌ی سرعت فروش در بازه‌ی تنظیم‌شده، روزهای باقی‌مانده تا اتمام، هشدار «رو به اتمام»، و ویجت داشبورد ووکامرس.

### گام ه — آماده‌سازی انتشار
یکسان‌سازی متن‌ها (انگلیسی به‌عنوان مبدأ)، تولید `.pot` و `.po/.mo` فارسی، `readme.txt`، `LICENSE`، `.distignore`، اسکریپت ساخت ZIP و CI.

> نکته‌ی مهم درباره محیط من: PHP روی این سرور نصب نیست و نمی‌توانم افزونه را واقعاً اجرا کنم. در عوض **سینتکس هر فایل PHP را با یک پارسر مستقل بررسی می‌کنم** و کد را با استاندارد WPCS می‌نویسم. تست واقعی روی وردپرس باید توسط خودت انجام شود؛ راهنمای دقیقش را هم می‌نویسم.

## ۷. تصمیم‌هایی که لازم است بگیری

1. **ترتیب گام‌ها:** با گام ب (نمایش در فروشگاه) شروع کنم یا اول پنل تنظیمات (گام الف) ساخته شود؟
2. **موضوع جدول‌های بی‌استفاده:** ۹ جدول بی‌مصرف فعلاً ساخته نشوند تا ماژول‌شان بیاید، یا همان‌طور بمانند؟
3. **زبان مبدأ متن‌ها:** انگلیسی شود (استاندارد، پیشنهاد من) یا فارسی بماند؟
4. **ظاهر نمایش پیشنهادها:** قالب پیش‌فرض خودمان بسازیم، یا صرفاً هوک و شورتکد بدهیم تا خود قالب سایت استایل بدهد؟
